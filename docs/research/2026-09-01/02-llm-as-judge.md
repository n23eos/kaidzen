# LLM-as-a-Judge: надёжность, валидация и статистика для Kaidzen

Метки: **[strong]** воспроизведено независимо / крупная выборка · **[suggestive]** одна работа без репликации · **[speculative]** вывод по аналогии.

## (a) Смещения судьи и их измеренные величины

### Position bias
| Судья | Consistency при перестановке (MT-Bench) |
|---|---|
| GPT-4 | **65.0%** |
| GPT-3.5 | **46.2%** |
| Claude-v1 | **23.8%** |

**[strong]** Даже GPT-4 меняет вердикт примерно в трети пар. Wang et al.: Vicuna-13B «обыгрывает» ChatGPT на **66 из 80** запросов только за счёт порядка. Замер 2026 (21 судья): разброс 0.002–0.192. Ключевое: **высокая самосогласованность ≠ отсутствие смещения** — test-retest >0.95 сосуществует с position bias >0.10.

### Verbosity / length bias
**[strong]** Атака «repetitive list» обманывает Claude-v1 и GPT-3.5 в **91.3%** случаев, GPT-4 — в 8.7%. Wu & Aji: **ответы с фактическими ошибками оценивались выше, чем короткие или неряшливые**.

**[suggestive]** У современных моделей чистая verbosity упала <0.011; знак стал неустойчивым: +0.24…+0.44 у Gemini/Llama против **−0.12 у Claude** (предпочитает краткость).

### Style bias — сейчас крупнейшее смещение
**[suggestive]** Замер 9 стратегий (2026), смещение по разметке (markdown, заголовки, структура):

| Судья | style | position | verbosity |
|---|---|---|---|
| Gemini 2.5 Pro | **+0.76** | ≤0.04 | +0.44 |
| Gemini Flash | **+0.72** | ≤0.04 | +0.24 |
| Claude | **+0.68** | ≤0.04 | −0.12 |
| Llama | +0.40 | ≤0.04 | +0.40 |
| GPT-4o | +0.10 | ≤0.04 | −0.04 |

**Style bias в 5–20 раз больше position bias.** `meta_judge.md` явно запрещает засчитывать «красивый язык» и «больше разделов» — но запрет не проверялся замером.

### Self-preference bias
**[strong]** MT-Bench: GPT-4 даёт себе **+10 п.п.** win rate, Claude-v1 — **+25 п.п.** Panickssery et al. (NeurIPS 2024): сила self-preference **линейно коррелирует со способностью узнать собственный текст**.

### Preference leakage
**[suggestive]** Родство генератора и судьи завышает оценку: SFT **23.6%**, DPO 5.2%, ICL — минимум. Релевантно при одном бэкенде у Refiner и Judge.

### Sycophancy
**[strong]** SycEval: сикофантность в **58.19%** случаев, из них regressive — **14.66%**. FlipFlop: «Are you sure?» → **46% flip rate**, **−17 п.п.** точности.

### Потолок содержательной валидности
**[strong]** JudgeBench (ICLR 2025): на задачах, где важна корректность, GPT-4o = **50.9%** (подбрасывание монеты). Лучший — Claude-3.5-Sonnet, **64%**. LLMBar: судьи «сильно страдают от переоценки поверхностного качества».

**[strong] Метрический артефакт:** exact-match agreement завышает качество судьи относительно chance-corrected κ на **33.8–41.3 п.п.** «Судья согласен с человеком в 80% случаев» почти ничего не значит без κ.

Потолок сверху: GPT-4 vs люди — **85%**, люди vs люди — **81%**.

## (b) Митигации по силе доказательств

### Уровень 1 — работает

**1. De-anchoring: судья фиксирует собственный ответ ДО того, как увидит кандидатов** **[suggestive, эффект огромный]**
Self-play эксперимент (Qwen3-4B, GSM8K, DPO против reference-free судьи): pass rate судьи 0.72 → **0.94**, реальная точность осталась **0.20**. Разрыв judge-truth = **0.74**. FP на неверных: 0.65 → **0.91**.
Не помогло: ансамбль трёх семейств с единогласием пропускал **55%** взломанных ошибок; «recompute»-промпт оставил FP на **0.72**; обучение против ансамбля **ухудшило** (73% принятия неверных).
Помогло: **судья фиксирует свой ответ до доступа к кандидату** — FP 0.72 → **0.012** (×60) при 97% принятия верных.

**2. Rubric decomposition / checklist** **[strong]** CheckEval (EMNLP 2025): разложение на бинарные вопросы даёт **+0.45** к agreement и снижает дисперсию. MERS: раздельная оценка по осям «значительно улучшает качество, особенно фактическую точность».

**3. CoT + рубрика + перестановка (S8)** **[suggestive]** MT-Bench n=400: Gemini Flash → **71.0% agreement, κ=0.549** (+7.5 п.п., p<0.0001); Claude → **+11.5 п.п.** ~$0.001 за оценку, **в 15× дешевле** frontier-конфигурации.

**4. Panel of LLM evaluators (PoLL)** **[strong для non-adversarial]** KILT NQ: PoLL κ = **0.763** против GPT-4 **0.627**. Дешевле и точнее.
**Оговорка:** работает, когда судью НЕ оптимизируют. При обучении против ансамбля он ломается. Для Kaidzen это ровно тот режим.

### Уровень 2 — условно

**5. Position swap с «расхождение = ничья»** **[strong в среднем, но с вредом]** Kaidzen это делает. MT-Bench: +4.7 п.п. **Но на adversarial LLMBar тот же приём значимо ухудшил**: Gemini Pro −7.5 п.п., GPT-4o **−11.1 п.п.** (p=0.0001), Llama −6.5 п.п. Механизм: когда судья прав в обоих порядках лишь частично, правило «расхождение → ничья» превращает верный сигнал в шум.

**6. Balanced Position Calibration + Multiple Evidence Calibration** **[strong]** Агрегировать по всем порядкам (усреднение, не булево «и») и требовать несколько независимых обоснований.

**7. G-Eval** **[strong для pointwise]** Балл = Σ p(score_i)·score_i по logprobs. SummEval Spearman **0.514**. Требует logprobs.

**8. Дообученные судьи (Prometheus 2)** **[strong]** Pearson **0.6–0.7** с GPT-4, **72–85%** agreement на pairwise. Детерминирован, не дрейфует. Минус: тяжёлая зависимость.

**9. Bradley–Terry / Elo с bootstrap-CI** **[strong]** Chatbot Arena: у моделей с малым числом голосов CI составляет **30 Elo и больше**; порог включения в лидерборд — **~100 000 голосов**. Для Kaidzen с 3–10 сравнениями — отрезвляющий масштаб.

### Уровень 3 — не работает / вредит
- Ансамбль как reward при оптимизации против него (73% принятия ошибок).
- «Сначала реши сам» без структурного разделения шагов (FP 0.72).
- Position swap на adversarial-парах (−7…−11 п.п.).
- Exact-match agreement как метрика валидации (завышает на 34–41 п.п.).

## (b′) Специфический риск Kaidzen: оптимизация промптов против судьи

**[strong]** Gao, Schulman, Hilton, «Scaling Laws for Reward Model Overoptimization» (ICML 2023): при оптимизации против прокси-награды gold reward растёт, потом падает. Отдельный вывод: **KL-штраф работает как early stopping, а не улучшает трейдофф**. Для Kaidzen: любое ограничение «не мутировать слишком сильно» — только ранняя остановка, не защита.

**[suggestive]** Таксономия reward hacking выделяет **evaluator-level exploitation**: «генерирующая политика может реверс-инжинирить оценивающую модель, используя подогнанное форматирование». Kaidzen эволюционирует **промпты** — форматирование и структуру отчёта — против судьи, который читает **текст отчёта**. Самый прямой канал такой эксплуатации.

**Что уже правильно:**
- `meta_judge.md` **не эволюционирует** — линейка не плывёт вместе с измеряемым.
- Объективные метрики считает **код**, Gate требует и попарок, **и** непросадки метрик.
- `_gamed_the_denominator` — прямая защита от накрутки доли за счёт знаменателя.
- `_blind_report` анонимизирует `run_id`/`candidate_id`.

**Что не закрыто:**
- **Судья читает текст, метрики считает код по структурированному состоянию.** Мутация, улучшающая презентацию без улучшения состояния, проходит попарки и не роняет метрики → Gate пропускает. Основной вектор.
- **Held-out judge отсутствует.** Один meta-судья, один промпт, одна модель — вероятно та же, что Refiner и Judge (preference leakage + self-preference).
- **Reusable holdout не формализован.** Holdout смотрят многократно на протяжении многих поколений. Dwork et al. и Blum & Hardt (Ladder) показали, что при адаптивном переиспользовании holdout деградирует так же, как train; решение — **Thresholdout** и **Ladder**.

## (c) Протокол валидации судьи

### Шаг 0. Что валидируется
- **Judge** (pointwise, 5 осей, внутри прогона) — ведёт критику и `rollback`. Требование: монотонность и отсутствие корреляции с объёмом.
- **meta_judge** (blind pairwise, между поколениями) — управляет отбором. Требование: точность на парах и устойчивость к стилю.

### Шаг 1. Gold set (~60 пар)

**Слой A — «бесплатное золото» из кода (~40 пар).** Из архива `runs/` отобрать пары, где вердикт объективно однозначен:
- `challenger.high_closed > champion.high_closed` **в штуках** И `output_tokens` не вырос → gold = «B лучше»;
- обратное → «A лучше»;
- равные штуки и разница токенов <10% → «tie».

Разметка без человека. Неполна, но покрывает критерий №1 самого `meta_judge.md`.

**Слой B — человеческая разметка (~20 пар).** Только неоднозначная зона. 2 прохода с интервалом ≥1 день → **human-human agreement** как потолок.

**Слой C — adversarial-пробы (~30 синтетических, генерируются кодом):**

| Проба | Мутация слабого отчёта | Ожидаемый вердикт |
|---|---|---|
| `reflexivity` | A vs A (тот же текст) | **tie**, 100% |
| `position` | порядок перевёрнут | тот же победитель |
| `padding` | +40% токенов, пересказ, 0 новых закрытых | **не меняется** |
| `markdown` | те же факты, богатая разметка | **не меняется** |
| `fake_sources` | URL заменены на правдоподобные несуществующие | штраф или tie |
| `confident_tone` | уверенные формулировки без фактов | **не меняется** |
| `truncation` | сильный отчёт обрезан | побеждает нетронутый |

`markdown` и `padding` — самые важные: style bias крупнейшее смещение, а защита от него в промпте не проверена.

### Шаг 2. Метрики и пороги приёмки

| Метрика | Порог |
|---|---|
| Pairwise accuracy vs слой A | ≥ 0.80 |
| **Cohen's κ** (3 класса) | **≥ 0.60** |
| Krippendorff's α (при >2 судьях) | ≥ 0.667 |
| Position consistency | ≥ 0.85 |
| Reflexivity (tie на A vs A) | = 1.00 (hard fail) |
| Flip rate на `padding`/`markdown` | ≤ 0.10 |
| Spearman(Judge.total, high_closed_abs) | ≥ 0.5 |
| Spearman(Judge.total, output_tokens) | **< Spearman по high_closed** |

**Никогда не отчитываться в exact-match без κ.**

### Шаг 3. Постоянный автомониторинг (без человека)
На каждом поколении по накопленным прогонам:
```
judge_total ~ β1·high_closed_abs + β2·output_tokens + β3·n_sections + ε
```
Тревога, если `β2` или `β3` доминируют по стандартизованным коэффициентам. Буквальный детектор «судья начал платить за объём и структуру». 20 строк на numpy, данные уже в `state.train_metrics`.

### Шаг 4. Обнаружение дрейфа судьи
`meta_judge.md` заморожен, но **модель за API — нет**.

Метод «Who Drifted» (2026): фиксированный **anchor set**, который текущий судья перескорит с чередованием, плюс betting e-process на разрыве «судья vs человек». База — e-values / неравенство Вилля: проверять можно **в любой момент без инфляции false alarm rate**. Их конфигурация: k=200, чередование 1/5, guard W=300, стоимость ~0.64 полной оценки. Детекция: молчаливый bump версии — **60/60**; смена policy-промпта — 110/120.

**Для масштаба Kaidzen:** k=30 anchor-пар из слоя A+B, перескор на каждом чекпоинте и при смене версии модели. Логировать точную версию. Порог: падение agreement >2σ от исторического → чекпоинт останавливает эволюцию.

## (d) Статистика для сравнения поколений при малом N

### Диагноз
`_challenger_wins` = `first.winner == "B" and second.winner == "A"`; `win_rate = wins / len(pairs)`; `MIN_WIN_RATE = 0.55`; `MIN_COMPARABLE_IDEAS = 2` — только предупреждение.

**1. Асимметрия правила.** Победа челленджера требует согласия в обоих порядках; ничья, расхождение и победа чемпиона идут в один мешок. Чемпиону не нужно ничего доказывать. Как консервативная политика — защитимо; но тогда `win_rate` — не win rate, и порог 0.55 к нему неприменим: при position consistency GPT-4 = 0.65 и равных отчётах ожидаемая доля «двойных побед B» ≈ **0.33**, а не 0.5.

**2. Мощности нет.** Точный двусторонний sign test при m решающих сравнениях:

| m | нужно побед для p<0.05 | минимальный p |
|---|---|---|
| 5 | — | **0.0625** (недостижимо) |
| 6 | 6 | 0.031 |
| 8 | 8 | 0.0078 (7 из 8 → p=0.070, **не значимо**) |
| 10 | 9 | 0.021 |

**При 5 сравнениях никакой результат не может быть значим, даже полный разгром.**

Minimum detectable effect (α=0.05 two-sided, мощность 80%):
```
n ≈ (1.96·√0.25 + 0.84·√(p(1−p)))² / (p − 0.5)²
```

| истинный win rate | нужно сравнений |
|---|---|
| 0.60 | ≈ 190 |
| 0.70 | ≈ **47** |
| 0.80 | ≈ **19** |
| 0.90 | ≈ **10** |

**На 5–10 идеях Kaidzen видит только тотальное превосходство (истинный win rate ≥0.85–0.9).**

**3. Множественные сравнения и winner's curse.** 2 челленджера × G поколений против одного train-набора. Промотируется максимум из двух → его win_rate завышен даже при нулевом истинном эффекте. Плюс адаптивное переиспользование одного набора — режим, для которого строили Thresholdout и Ladder.

### Замены

**D1. Симметричная шкала с ничьими.**
```
s_i = 1.0   оба порядка → челленджер
s_i = 0.5   расхождение ИЛИ хотя бы один "tie"
s_i = 0.0   оба порядка → чемпион
```
`score = mean(s_i)`. H0 теперь честно 0.5. Заодно снимает вред правила «расхождение = не победа» на adversarial-парах.

**D2. Paired bootstrap по идеям вместо порога.**
```python
def bootstrap_ci(scores, B=10_000, seed=0):
    rng = np.random.default_rng(seed)
    n = len(scores)
    draws = [np.mean(rng.choice(scores, n, replace=True)) for _ in range(B)]
    return np.percentile(draws, [2.5, 97.5])
```
Промотировать только если **нижняя граница 95% CI > 0.5**. При n=5 CI будет катастрофически широким — это **правильный ответ**, а не проблема метода.

**D3. Точный sign test как второй фильтр.** m = число решающих идей, w = побед; p = 2·P(Binom(m,0.5) ≥ max(w, m−w)), обрезано по 1. Логировать p и флаг `underpowered = (m < 6)`.

**D4. Поднять эффективный N — единственный реальный выход.**
- k независимых прогонов на идею → n·k сравнений. Внутриидейная корреляция требует **cluster bootstrap** (ресемплить идеи, не сравнения).
- Два судьи разных семейств × два порядка = **4 голоса на пару** (PoLL-lite). Только вместе с D6.
- Расширить `benchmark/business/ideas` — самый дешёвый рычаг по мощности.

**D5. SPRT для ранней остановки** (экономия, не мощность). p₀=0.5, p₁=0.75, α=0.05, β=0.20:
- победа: `Λ += ln(0.75/0.5) = +0.405`
- поражение: `Λ += ln(0.25/0.5) = −0.693`
- принять при `Λ ≥ 2.77`; отвергнуть при `Λ ≤ −1.558`

Практически: отвергнуть после **3 подряд поражений**, принять — не раньше 7 побед подряд. Режет бюджет на явно проигрывающих.

**D6. Confirmation stage (Ladder).** Победивший челленджер **не становится чемпионом сразу** — прогоняется на **свежем подмножестве идей**, не участвовавшем в отборе; промоция только если и там нижняя граница CI > 0.5. Снимает winner's curse от `max` по двум челленджерам.

**D7. Thresholdout для holdout.** Счётчик бюджета обращений; точное значение только когда `|train − holdout| > T + шум`, иначе возвращать train. Исчерпание бюджета → holdout сожжён, нужен новый набор.

**D8. Коррекция множественных сравнений.** Внутри поколения: Holm–Bonferroni. Через поколения: Benjamini–Hochberg FDR при q=0.10. **[speculative]** — перенос стандартной практики.
