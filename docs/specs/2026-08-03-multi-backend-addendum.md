# Дополнение к ТЗ: сменные бэкенды моделей

Дополняет `2026-08-03-idea-refinement-loop-tz.md`. Заменяет §2.3 («Модели») и часть §3 (`config.yaml`).

**Дата:** 2026-08-03
**Причина:** прогон должен быть возможен без платного API-ключа — через подписку Claude, — и при этом допускать подключение ключей OpenAI и DeepSeek.

---

## 1. Что меняется

Раньше роль знала только имя модели, а транспорт был один — Anthropic API. Теперь роль знает **бэкенд + модель**, а бэкендов четыре. Это позволяет: гонять весь цикл бесплатно на подписке; удешевлять отдельные роли на DeepSeek; сравнивать модели разных вендоров на одной идее.

### Проверено экспериментально (до написания кода)

- Claude Agent SDK запускается из Python на подписке, без `ANTHROPIC_API_KEY`, и возвращает чистый JSON.
- Веб-поиск через него работает и **виден в потоке** как `ToolUseBlock` с `name="WebSearch"`.
- В контрольной пробе модель вернула точную цену и правдоподобный URL, **не сделав ни одного поиска** — источник был взят из памяти. Отсюда обязательное требование §4.

---

## 2. Бэкенды

| Бэкенд | Тип | Ключ | Веб-поиск | Structured output |
|---|---|---|---|---|
| `subscription` | `claude_agent_sdk` | не нужен (подписка) | да, tool `WebSearch` | JSON по схеме в промпте + валидация |
| `anthropic` | `anthropic` | `ANTHROPIC_API_KEY` | да, `web_search_20260209` | tool-use `submit` со схемой |
| `openai` | `openai_compat` | `OPENAI_API_KEY` | да, Responses API | `response_format: json_schema, strict` |
| `deepseek` | `openai_compat` | `DEEPSEEK_API_KEY` | **нет** | `response_format: json_object` + схема в промпте |

Каждый бэкенд объявляет способности; загрузчик конфига читает их и валидирует расстановку ролей.

---

## 3. Конфиг кандидата

Секция `models` заменяется на `backends` + `roles`:

```yaml
backends:
  subscription: { type: claude_agent_sdk }
  deepseek:     { type: openai_compat, base_url: "https://api.deepseek.com", api_key_env: DEEPSEEK_API_KEY }

roles:
  analyzer:   { backend: subscription, model: claude-sonnet-5 }
  researcher: { backend: subscription, model: claude-sonnet-5 }
  refiner:    { backend: subscription, model: claude-sonnet-5 }
  judge:      { backend: subscription, model: claude-sonnet-5 }
  reporter:   { backend: subscription, model: claude-sonnet-5 }
```

Правила валидации при загрузке кандидата (все — до первого платного вызова):

1. Заданы ровно пять ролей: четыре рабочих плюс `reporter`.
2. Каждая роль ссылается на бэкенд, объявленный в `backends`.
3. **Бэкенд роли `researcher` обязан поддерживать веб-поиск.** Иначе кандидат отвергается с явным сообщением. Это защита от «полирования в вакууме»: без поиска Researcher не может закрывать допущения фактами.
4. Для бэкендов с ключом: имя переменной окружения задано и **непустое на момент запуска** — иначе отказ на старте, а не на пятой минуте.

Три поставляемых кандидата (`generic`, `business`, `games`) переезжают на `subscription` для всех ролей — чтобы из коробки работало без ключей.

---

## 4. Обязательная проверка факта поиска

Researcher возвращает факты со ссылками. Ссылка ценна только если взята из результатов поиска, а не из памяти модели — экспериментально показано, что модель охотно выдаёт правдоподобный URL, не поискав.

Требование: бэкенд, выполняющий вызов с включённым поиском, обязан сообщать вызывающему, **сколько поисков реально произошло**.

- `subscription`: считать `ToolUseBlock` с `name="WebSearch"` в потоке.
- `anthropic`: `usage.server_tool_use.web_search_requests`.
- `openai`: число вызовов web-search-инструмента в ответе.

Если поиск был запрошен, но не выполнен ни разу, — вызов считается несостоявшимся и повторяется через обычный retry-путь роли. После исчерпания попыток шаг падает: лучше остановить прогон, чем записать в отчёт выдуманный источник.

---

## 5. Ключи

Порядок разрешения: переменная окружения → файл `.env` в корне проекта. Явный ключ в `config.yaml` запрещён — только имя переменной.

`.env` добавляется в `.gitignore`; в репозитории лежит `.env.example` с пустыми полями. Ключи не логируются, не попадают в `state.json` и не печатаются в прогресс-выводе.

---

## 6. Что не меняется

Контракты ролей, схемы состояния, критерии остановки, реестр допущений, формат отчёта, resume. Бэкенд — это только транспорт; логика цикла его не видит.

---

## 7. Ограничения

- **DeepSeek не умеет искать.** Он пригоден для Refiner и Judge, но не для Researcher; конфиг это проверяет.
- **Подписка ограничена лимитами Claude**, а не деньгами: длинный прогон может упереться в лимит. Ошибка лимита обрабатывается как временная — с повтором.
- **Structured output на подписке и DeepSeek слабее**, чем tool-use со схемой: модель просят вернуть JSON и валидируют результат. Существующий повтор с текстом ошибки валидации это закрывает, но одна лишняя попытка на таких бэкендах вероятнее.
